# AI補完記録0530

## 概要
- VR空間内で家（部屋）を自動生成し、Meta Quest等のVRデバイスで体験するUnityプロジェクトの開発メモ。
- 主な課題は「VRデバイスの認識」「Input Systemの設定」「家の生成・表示確認」など。

---

## 1. Input SystemとXR設定

- **Input Action Asset**は、コントローラーやキーボードの入力をアクションに割り当てる設定ファイル。
- **Input Action Manager**にアセットを割り当てるだけではコントローラーは動かない。  
  各Move/Turn Providerの「Input Action Reference」に正しいアクション（例：XRI LeftHand/Moveなど）を割り当てる必要がある。
- **Active Input Handling**は「Input System Package (New)」に設定するのが推奨（BothはAndroid非対応＆不具合の元）。

---

## 2. VRデバイス認識・トラブルシュート

- Input DebugでコントローラーやHMDが表示されていなければ、UnityがVRデバイスを認識できていない。
- Meta Questの場合はOculusアプリを起動し、Oculus Link/Air LinkでPCと接続。
- SteamVR経由で使いたい場合はSteamVRアプリも起動し、XR Plug-in Managementで「OpenVR Loader」を有効化。
- どちらか一方（OculusまたはOpenVR）だけ有効にするのがトラブルが少ない。

---

## 3. HouseBuilder.csによる家の自動生成

- HouseBuilder.csで部屋・床・ドア・ランドマークなどを自動生成。
- カメラの前方にCubeを生成して「見えるか」確認する処理も追加。
- XR Originの初期位置は部屋の中央や入口付近、床の上など任意に設定可能。

---

## 4. Prefab化と手動配置

- 自動生成した家（HouseRoot）をPrefab化し、Projectウィンドウに保存。
- Prefabをシーンにドラッグ＆ドロップして、再生前に家を配置できる。
- XR Origin（カメラ）も手動で家の中に移動し、Gameビューで見えるか確認。

---

## 5. よくある問題と対策

- **家や床が見えない場合**  
  → Prefabのスケール・位置・カメラの位置や向きを確認。  
  → ライトやマテリアルの設定もチェック。
- **頭を動かしても視界が変わらない場合**  
  → XR OriginのカメラがVRデバイスにバインドされていない、またはデバイス未認識。
- **コントローラーで移動できない場合**  
  → Input Action Assetの割り当てやInput Systemの設定を再確認。

---

## 6. 今後の進め方

1. Prefab化した家をシーンに配置し、まず「家が見える」状態を作る。
2. カメラ（XR Origin）を家の中に手動で移動し、視点が正しいか確認。
3. VRデバイスやコントローラーの認識・Input Systemの設定を再度見直す。
4. 必要に応じてエディタ拡張や手動配置で開発効率を上げる。
