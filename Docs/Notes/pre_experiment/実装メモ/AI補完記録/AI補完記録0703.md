# AI補完記録 0703

## 1. ログ保存の現状と課題
- UnityのLogger.csでログを`Application.persistentDataPath`に保存。
- Meta Quest 3（Android 11以降）ではこのパスは`/storage/emulated/0/Android/data/<パッケージ名>/files/`となり、アプリ内からはアクセスできるがPCからは直接アクセス不可。
- DownloadやDocuments等に自動コピーしようとしたが、Android 11以降のストレージ制限（Scoped Storage）により「Access to the path ... is denied.」エラーで全て失敗。
- persistentDataPathには保存できているが、ユーザーがPCで簡単に取得できない。

## 2. Logger.csの自動コピー機能の問題
- TryCreateAccessibleCopyやCopyLogToAccessibleLocationで外部ストレージへの自動コピーを試みていたが、Android 11以降では仕様上不可能。
- 権限リクエストやパス変更でも回避不可。
- Quest 3実機でadb logcat確認→大量のアクセス拒否エラー。

## 3. 対応策・リファクタリング
- Logger.csの自動コピー機能（TryCreateAccessibleCopy, CopyLogToAccessibleLocation, useAlternativePath等）を完全削除。
- ログは`Application.persistentDataPath`にのみ保存するシンプルな構成に。
- ログの外部エクスポートはLogExporter.cs＋NativeFileSO（SAF対応プラグイン）経由のみに一本化。

## 4. LogExporter.csとNativeFileSOによるエクスポート
- LogExporter.csでLoggerから最新のログファイルパスを取得。
- NativeFileSOを使い、ユーザー操作でエクスポートダイアログを表示。
- ユーザーが保存先（Download等）を選ぶことでQuest外部ストレージにログをコピー可能。
- Yボタン（Input System経由）でエクスポートを実行。

## 5. Input System/XR Interaction Toolkit対応
- Yボタン検出はInput Actionsアセット＋InputActionReferenceで確実に動作するよう修正。
- Inspector未設定時の警告やデバッグログも追加し、動作確認・トラブルシュートしやすくした。

## 6. 関連ファイル一覧
- `Assets/VRMoL/Scripts/UI/Logger.cs` … ログの生成・保存（自動コピー機能は削除済み）
- `Assets/VRMoL/Scripts/UI/LogExporter.cs` … ユーザー操作によるエクスポート機能
- `Assets/XRInputActions.inputactions` … Yボタン等の入力定義（Input System）
- `Assets/nativefileso-master/Assets/NativeFileSO/` … NativeFileSO本体（SAF対応プラグイン）

## 7. 今後の運用・推奨フロー
- ログの自動コピーは諦め、ユーザー操作によるエクスポートのみを案内。
- Logger.csは「Quest内のpersistenceDataPathに保存」だけに専念。
- ログを取り出したい場合はYボタンでエクスポートダイアログを出し、ユーザーが保存先を選ぶ。
- 必要に応じて、UIやマニュアルで「Yボタンでエクスポートできます」と案内。

## 8. 補足・注意点
- これはAndroid 11以降の仕様による制限であり、UnityやMeta Quest固有の問題ではない。
- 今後もGoogle/Metaの仕様が変わらない限り、自動コピー復活は不可能。
