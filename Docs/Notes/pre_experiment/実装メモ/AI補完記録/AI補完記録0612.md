## 1. ロケーション間移動方式の検討

これまでの設計では、各ロケーション（部屋）をドアでつなぎ、ユーザーがドアを通過することで次のロケーションへ移動する方式を採用していた。

今回、以下の新たな移動方式も検討・提案：

### ● ワープ（瞬間移動）方式
- 各ロケーションで単語カードの配置が完了したら、次のロケーションへワープ（瞬時に移動）できる。
- ワープのトリガー方法は2パターン：
  1. メニュー画面の「次へ」ボタンを押す
  2. コントローラーの特定ボタン（例：Aボタンやトリガー長押し）でワープ
- 進行条件（例：単語カード配置完了）を満たした場合のみワープ可能にする。
- UI上に「ワープ可能」などの表示を出すと親切。

#### 実装イメージ（Unity/C#）
```csharp
public class LocationManager : MonoBehaviour
{
    public Transform[] locationPoints; // 各ロケーションのワープ先
    private int currentLocation = 0;

    public void WarpToNextLocation()
    {
        if (currentLocation < locationPoints.Length - 1)
        {
            currentLocation++;
            // プレイヤーの位置をワープ
            Camera.main.transform.position = locationPoints[currentLocation].position;
            // 必要なら回転も
            Camera.main.transform.rotation = locationPoints[currentLocation].rotation;
        }
    }
}
```
- UIボタンやコントローラー入力から `WarpToNextLocation()` を呼び出すだけでOK。

#### メリット
- テストやデバッグが容易
- ユーザーが迷いにくい
- ロケーション間の音声漏れリスクが減る

#### デメリット
- 没入感がやや減る場合がある（UIや演出でカバー可能）

#### 備考
- ドア移動とワープ移動を併用し、実験条件やユーザー選択で切り替えることも可能。
- ワープ時の演出（フェードイン・アウト等）を加えるとUX向上。

## 2. 進捗・アセット準備状況の管理

- ロケーション４（リビング）：ほぼ完成
- ロケーション５（キッチン）、６（洗面所）：空間設計完了、次は家具などの生成
- 進捗管理表・アセット準備状況表を各ロケーションごとに細分化し、チェックリスト形式で管理
- 進捗状況やアセット準備状況はDocs/Notes/pre_experiment/実装メモ/進捗状況/進捗状況.mdにて随時更新

## 3. 設計・実装ガイドライン（要点）

- 各ロケーションは5m×5m×3mで統一
- Blenderで基本モデル作成、ポリゴン数・テクスチャサイズ制限あり
- Addressablesによるアセット管理
- 音声は1分ループ、-28LUFS統一
- 単語カードはPrefab＋スクリプト自動生成、40単語から各部屋に2単語ランダム配置
- 実験データはCSV等でローカル保存
- UIは進行状況やワープ可否を分かりやすく表示
